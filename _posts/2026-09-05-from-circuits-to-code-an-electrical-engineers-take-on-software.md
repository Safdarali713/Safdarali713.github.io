I'm an Electrical Engineering student, specializing in Power — so it's a fair question when people ask why I spend so much time writing code on the side. Here's the short answer: circuits and code aren't as different as they look. Both are about signals, logic, and getting a predictable output from a system.



In Power engineering, you're always thinking in terms of flow — current flowing through the right path, load balanced correctly, a system designed so that input reliably produces the output you expect. Whether I'm solving a circuit problem in Multisim or modeling a system in MATLAB, the core skill is the same: understand the system, predict how it behaves, and design around that.



That mindset carried directly into my first real software projects, built with Python and FastAPI. Instead of current flowing through a circuit, it's data flowing through logic: input comes in, gets routed through the right decision paths, and produces a useful output on the other end. The engineering instinct didn't change. Only the medium did.



One of those projects didn't go exactly as planned — not every system works on the first design, in circuits or in code — but working through it taught me the same patience that debugging a faulty circuit does: isolate the fault, test one variable at a time, and don't assume anything until you've verified it.



I don't see software as a departure from electrical engineering. I see it as another system to design — just one where the components are logic and structure instead of resistors and relays. Power systems taught me how to think in systems. Code just gave me a faster way to build them.



I'm still early in this — a student, a freelancer, and an engineer figuring out how these two worlds connect long-term. More updates on my projects and what I'm learning will follow here.
